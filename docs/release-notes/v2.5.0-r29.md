# v2.5.0-r29 — update from the touchscreen; accented tracks load whatever the mount does

<!-- debs: rebuild -->

New Mixxx build and a skin/Pi-script update. Two changes, one of them a
follow-up to r28 that fixes the case that was actually biting.

- **Tracks with accented filenames now load however the stick is mounted**
  (`rekordbox-path-fallback.patch`, patch 21). r28 shipped two things for
  this: a mount fix (`utf8=1` on FAT sticks) and a Mixxx fallback. The Mixxx
  fallback only covered a disagreement about Unicode *normalisation*, which
  turned out to be the wrong half. The real case is a stick mounted without
  `utf8`, where the kernel hands the accented character back in its own
  default character set — something no normalisation of the name in
  `export.pdb` can ever match. So if the mount script had not been updated
  (see below), r28 changed nothing you could see.

  Mixxx now falls back further: when the exact name and both normalisations
  miss, it lists the folder and matches the track on the **ASCII part of its
  name**. Every mangling of an accent leaves that part identical, so the file
  is found whatever the mount did to it. Two files whose names differ *only*
  in accented characters are refused rather than guessed between, and a match
  logs a warning, because needing this at all means the stick is still
  mounted wrongly and the mount fix is worth getting in place.

- **SOFTWARE UPDATE in the settings menu** (`update-page.patch`, patch 22).
  The cog panel gains a SOFTWARE UPDATE entry above POWER OFF. It opens a
  page that runs the updater on the Pi and shows its **terminal output live**,
  line by line, exactly as it would look in a shell — so the unit updates
  itself with no ssh session and no keyboard.

  UPDATE is tap-again-to-confirm, like POWER OFF. While it runs, the buttons
  withdraw, because apt is part-way through dpkg and there is nothing safe to
  press; the log keeps scrolling and is dragged with a finger. When it
  finishes cleanly, **RESTART NOW** appears — the new build only takes effect
  once Mixxx restarts. Closing the page, or the whole menu, deliberately
  leaves a running update running.

  `update-pioneered.sh` gained a no-reboot mode for this, and now installs
  itself to `/usr/local/bin/` so the button has a fixed path to call.

## If you are on r27 or r28

Two things worth knowing before you update.

The r28 release was published about eighteen minutes after its tag, because
the debs are built from source on a tag push. Running the updater during that
window installed r27, correctly — r28 did not exist yet. If you saw that, it
was timing, not a fault.

More importantly: the step that installs the mount script lives *inside* the
r28 updater. Running an older copy of the script updates the debs but leaves
the old mount script in place, which is why accented tracks could still fail
on r28. **Use the updater from this release**, which installs the whole `pi/`
layer and itself:

```
curl -fL -o update-pioneered.sh \
  https://raw.githubusercontent.com/marcosseris/Pioneered/v2.5.0-r29/pi/update-pioneered.sh
chmod +x update-pioneered.sh
sudo ./update-pioneered.sh
```

After this one, the SOFTWARE UPDATE button can do it for you.

## Install (on the Pi)

```
sudo ./update-pioneered.sh
```

The reboot at the end remounts the sticks with the right options. For the
update button to work later, add the sudoers rule from README §6.

## Field checks

### Accented filenames

1. Browse to *BASTI - La Mamá* and tap LOAD 1. It **loads**, and the screen
   returns to Overview.
2. It should load whether or not the mount is fixed. To confirm which path
   you are on, run `mount | grep USBA`: with `utf8` in the options the name
   matched directly; without it, the log (`journalctl --user -u mixxx`, or
   wherever Mixxx logs) carries a `Rekordbox: matched …` warning naming the
   mount fix. Either way the track plays.
3. A rekordbox entry whose file really is gone still shows
   **TRACK FILE NOT FOUND ON USB** rather than doing nothing.
4. Re-import a stick with many accented tracks and check the import is not
   noticeably slower than before.

### Software update

5. Cog → **SOFTWARE UPDATE**. The page opens with the log empty and
   "TAP UPDATE TO CHECK FOR A NEW VERSION".
6. Tap **UPDATE** once: it turns red, "TAP AGAIN TO UPDATE". Wait 5 s — it
   goes back on its own. Tap it twice: the log starts filling with the
   updater's output, the buttons disappear and the status reads
   "UPDATING… DO NOT POWER OFF".
7. Drag the log with a finger while it runs: it scrolls, and new output keeps
   arriving at the bottom.
8. Let it finish. Since you are already on the newest release it reinstalls
   the same one and ends with **UPDATE INSTALLED — TAP RESTART TO FINISH**
   and a **RESTART NOW** button. Tap it: the unit reboots.
9. Without the sudoers rule from README §6, step 6 instead ends quickly with
   **UPDATE COULD NOT START** and a line about a password being required.
   Nothing is installed and nothing is broken.
10. Open the page, start an update, then tap the cog to close the whole menu.
    Re-open the cog: you land back on the **update page** with the log still
    running, not on the main menu. BACK does nothing until it finishes.
11. With no update running, BACK from the page returns to the menu, and the
    cog closes everything and reopens on the **main menu**.
12. Playback underneath is untouched throughout — though an update restarts
    Mixxx at the end, so do not run one mid-set.
