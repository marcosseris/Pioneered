# v2.5.0-r34 — the BPM number holds still, reads to one decimal, and is the truth

<!-- debs: rebuild -->

New Mixxx build **and** a skin change — install both.

- **It stops twitching.** The deck's BPM used to drift a few hundredths up and
  down while a track played, which is exactly what makes a number unreadable.
  The cause was in the import, not the display: rekordbox writes every beat's
  time rounded to a whole millisecond, and Mixxx read those rounded times as a
  track whose tempo changes at every single beat. It then measured the deck's
  BPM over an eight-beat window, and the rounding walked that measurement back
  and forth forever.

  The file already knew better — it records the tempo at each beat as well as
  the time — so when that tempo never changes, the beatgrid is now rebuilt
  from that exact number. The grid ends up within half a millisecond of
  rekordbox's own, anchored on the same downbeat, so the red bar markers land
  where they always did. Tracks with a grid that genuinely changes tempo are
  left exactly as they were.

- **One decimal, like a CDJ.** `140.0`, not `140.00`.

- **And the number is the tempo.** This is the part rounding alone would have
  faked: two decks could both have shown **140.1** while one ran at 140.14 and
  the other at 140.06, and you would have had no way to see it. So the tempo
  itself now moves in whole **0.1 BPM** steps. The pitch fader lands on a step,
  and a freshly loaded track is put on a step too rather than inheriting
  whatever rate the last track left the fader at. Two decks showing the same
  number are the same speed.

  The fader is 14-bit — about 16 000 positions across its travel — so at
  140 BPM and ±8% one step is roughly 0.45% of the fader. You cannot feel the
  stepping; you can only see it in the number.

- **SYNC is untouched.** A synced deck takes its rate from its leader, and the
  leader is already on the grid, so nothing is snapped underneath sync.

## Install (on the Pi)

```
sudo update-pioneered.sh
```

or Cog → **SOFTWARE UPDATE** → UPDATE, twice.

## Field checks

1. Load a rekordbox track and let it play. The BPM reads **one decimal** and
   the digit does not move — watch it for a full minute, including across a
   drop or a breakdown.
2. The number should be the track's real BPM (compare it with the BPM column
   in the browser, and with what rekordbox says).
3. Nudge the pitch fader a hair. The readout steps **0.1 at a time** — it
   never shows an intermediate value and never sticks.
4. Run the fader from end to end: the number sweeps smoothly in 0.1s and the
   ± % display beside it still tracks the fader.
5. **The one that matters.** Load a different track on each deck and beatmatch
   them by fader until both read the same number. They should *stay* matched —
   listen for a couple of minutes with both playing.
6. Load a new track onto a deck whose fader is parked off-centre and do not
   touch anything: the BPM shown is already on a 0.1 step (nudge the fader one
   step and back, and the number returns to the same value it had).
7. **Beatgrid check.** The red bar markers on the waveform still sit on the
   downbeats, and cue points and loops still land where they did.
8. Press **SYNC** on a deck: it matches the other deck and stays matched.
9. Nudge the jog side ring of a playing deck. The pitch bends as it always
   did, and the BPM readout stays on the fader's value rather than jumping
   around with the nudge.
10. Load a track with no beatgrid at all: the readout shows `0.0` rather than
    anything odd, and loading a gridded track afterwards recovers.

## Note

This build has not been run on hardware. The patch series was verified to
apply and round-trip cleanly against Debian trixie's Mixxx 2.5.0 source, and
the skin XML parses, but everything above is a check to perform, not a check
that has been performed.

Check 5 is the one worth doing properly — it is the whole reason the tempo is
stepped rather than just the display rounded.
