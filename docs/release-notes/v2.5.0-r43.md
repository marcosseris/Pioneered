# v2.5.0-r43 — Crash fix, and Mixxx comes back by itself

<!-- debs: rebuild -->

New Mixxx build and a new helper script on the Pi. Install the update as
usual.

- **Fixed: Mixxx crashing while browsing a rekordbox playlist.** Scrolling
  onto some tracks with memory cues could make Mixxx close without warning.
  This was a bug in Mixxx's own rekordbox import: it could look for the
  track's main cue before the cue existed. The import now creates the main
  cue when it is missing, so these tracks load normally.

- **Mixxx restarts itself if it ever crashes.** A small watchdog now starts
  Mixxx at boot and keeps it running. If Mixxx closes unexpectedly, it is
  back on screen in a few seconds, without rebooting the Pi. Hold-to-restart
  works the same as before. If Mixxx keeps crashing straight after it starts,
  the watchdog waits 30 seconds between tries.

  The updater turns the watchdog on by replacing the `mixxx &` line in
  `~/.config/openbox/autostart`. It takes effect from the next reboot.

## Install (on the Pi)

```
sudo update-pioneered.sh
```

or Cog → **SOFTWARE UPDATE** → UPDATE, twice.

Run the update **twice**. The first run installs the new updater, and the
second run uses it to turn on the watchdog. Then reboot.

To see restarts later: `journalctl -t mixxx-watchdog`.
